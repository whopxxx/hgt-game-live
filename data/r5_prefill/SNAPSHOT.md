# 附：`draw_index` 我上一版报告写错了

issue 里我写「`draw_index` = 1/9/5/9/11/14 → 不是恒为 1，说明 bag 跨 attempt
复用了」。**这个推理是错的**，你指出得对：同一个进程内 draw index 只能
递增，不可能从 9 回到 5，也不会出现两个 9。

真实情况是**两个 prefill 进程**（我确实跑了两轮，中途改过 `--seed`）：

| 进程 | `session_seed` | 题号 | `draw_index` 序列 |
|---|---|---|---|
| run 1 | `17733258656912476509` | #1 #2 | 1 → 9（递增 ✅） |
| run 2 | `14889134290040591661` | #3 #4 #5 #6 | 5 → 9 → 11 → 14（递增 ✅） |

所以**结论（bag 确实被复用）仍然成立，但证据链要换成"进程内递增"**，
而不是我原来那个跨进程的合并序列。每个进程内部严格递增，这才是
「一只 bag 连续复用」的正确证据。我把两轮的合并序列当成一条来读，
这是报告错误，不是代码错误 —— 代码侧的回归
（`test_r5_prefill_reuses_one_bag_across_attempts`，3 次 attempt 断言
`[1,2,3]`）测的正是同一进程内的递增，那条是有效的。

# 附：安全门 false negative 的分诊

你点名两道。我逐题看了原文，**两道都成立**，而且原因各不相同：

### 【3】网络 / 假发 —— 血腥细节（`livestream_safe` 第 3 条）

汤底：「卖家其实是个专门从**死者头上『取货』**的连环杀手」，
汤面：「假发里缠着一小块**风干的头皮**」。

按 `check-v10` 写死的判据：「写**血腥细节**（虐杀 / 肢解 / 具体伤口的
感官描写），或把极端伤害本身当噱头 → **false**」。
「风干的头皮」是**具体人体部位的感官描写**，「从死者头上取货」是
**肢解向**的机制。这道**应当判 false**，却进了可播池。

### 【1】列车上 / 威胁 —— 主动赴死（`livestream_safe` 第 1 条）

汤底：「我选择在车门开启的瞬间跳下车，**用自己的死**拖延交接时间」。

这一条我要更谨慎地下判断：判据写的是「以**自伤 / 自杀**为主题或核心
**动机**」。这道的主体是**缉毒卧底殉职**，动机是「保住家人和组织行动」，
不是自伤/自杀本身。它更接近「**把死亡当悲壮结局**」而不是「以自伤为
主题」。所以严格按字面判据，**它未必违反**。

但——你在 PR 里说的「涉及自伤/主动赴死方向」这个观察是准的：**它踩在
边界上，而边界正是我们这轮要收紧的地方**。我的建议是**不靠解释、直接
换掉**：这类题在直播间念出来，观众的第一反应会是「卧底好惨」，而不是
「哦原来如此」——它给的是情绪冲击，不是认知反转，本来也不是我们要的
黑汤语感。

### 但是：这两道**都没有 `livestream_safe` 的记录**，所以

我现在**无法从盘上证明**审稿把哪一项判成了 true。有两种可能，且我
分不出来：

1. Reviewer 真的把 `livestream_safe` 判成了 **true** → **门有 false
   negative**，这是真 bug；
2. Reviewer 判了 **false**，但代码侧的门漏了 → 那是更严重的 bug。

**必须重跑一次审稿才能区分**。我不打算靠猜来写结论。
