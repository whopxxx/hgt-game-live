## 1. 当前内容为什么显得直白？（代码 + 样本两面回答）

### 代码面

闭环源头是 **`fair_clues` 这条契约**（`story/quality.py:719-801`）：

```
"没有 fair_clue(谜面里必须有可回溯的线索)"           -> fail
"fair_clue 的 quote 不在谜面里"                      -> fail
"没有 fair_clue 支持任何 required atom"              -> fail
```

它把"公平"实现成了「**答案的逐字证据必须已经写在谜面上**」。再叠加
Stage A prompt 第 3 步那句 *"如果有一条关键步骤在谜面里完全没有痕迹，
回到第 2 步补一条线索"*（`story/llm.py:2370`），生成器被**两次**要求
把证据往谜面里塞。结果就是谜面从"一个让人想问的切片"退化成
"完整的现场说明"，而谜底只剩一件事可做：把这些已写出的证据串起来。

**详细规则表见 `audit.md` §1**（每条都有文件行号 + 副作用 + 建议）。

### 样本面（这是最直接的证据）

A 臂 8 道里，**7 道的结构完全是同一个形状**：

| # | 关键词 | 结构 |
|---|---|---|
| A-1 | 爱，故障 | 机器人"爱"模块过载 → 停在走廊重复"我爱你" |
| A-2 | 梦，画家 | 睡眠障碍 → 白天无意识作画 → 以为画的是梦 |
| A-4 | 转弯，录像 | 路牌画了弯 → 司机绕弯撞货车 → 录像断电只留直路 |
| A-5 | 人鱼公主，住院 | 并腿石膏 + 水疗池 → 被传成"人鱼公主" |
| A-6 | 长椅，怀孕 | 男人把冻货绑肚子装孕妇躲盘查 |
| A-7 | 铁杆，冰淇淋 | 舔铁杆粘住舌头 → 温水浇 + 冰淇淋冰敷 |
| A-8 | 跟踪，双胞胎 | 妹妹顶替死去的姐姐嫁人 → 姐姐其实没死 |

读起来是：**出现一个反常 → 问为什么 → 一个可解释的现实机制**。
A-3（母亲穿红羽绒服找女儿被雪埋，女儿看成"会走路的红衣服"）和
A-6 是这 8 道里最好的两道 —— 它们的共同点是**谜底重新定义了谜面里的
一个词**（"红衣服"、"孕妇"），而不是"补一段之前没说的背景"。

A 臂还有一个**结构性缺陷的直接证据**：A-8 的 `core_truth` 里出现了
自我怀疑的原文——

> ……那其实是姐姐的孪生存在感对她自己的心理投射?——不，唯一真相是：……

模型在**同一个字段里**先写了一个解释、划掉、再写第二个。这是
"一次调用同时完成创作 + 结构 + 文案"（§1.12）的典型症状：它在
填格子的过程中才发现自己的真相站不住。

## 2. 哪些生产规则在主动塑造这种风格？

完整表在 `audit.md` §1 / §6。这里只放**影响最大的六条**：

| # | 规则 | 文件 | 当前作用 | 副作用 | 建议 |
|---|---|---|---|---|---|
| 1 | `fair_clues` 必须逐字预置 + 必须支持 required atom | `quality.py:719-801` | 3 条 `fail`（整稿拒） | **"谜面=案情说明"的源头**：逼证据进谜面 | **放宽**（拆成"异常锚点 hard"+"QA 可获得"，quote 从必需变可选） |
| 2 | "好不好玩"四项作为自由生成**硬门** | `llm.py:1678/1864/6019` | 任一项非 true → 整稿拒 | 全灭单核经典汤。**curated 侧已降为信号**，理由写得一模一样却只放开了 curated | **`concrete_anomaly`/`clue_recontextualized`/`dramatic_payoff`/`reasoning_beats_nonredundant` 降 soft**；正确性五项保留 hard |
| 3 | `discovery_beats` 强制 2~4 | `quality.py:415/835`、`llm.py:1953/6095` | **两道门**：schema `minItems:2` + validate fail | 单层翻转结构上不可能合格 | **改成观察指标**（允许 1~4 或空） |
| 4 | 谜面结尾必须问句 | `puzzle.py:991`、`quality.py:441`、`llm.py:5557` | can_fix → **实为硬改**（改不掉就 rewrite） | 把"自明其问"的谜面加尾巴，**缩小**提问方向 | **放宽**成"含可调查异常" |
| 5 | 第一人称硬改第三人称 | `puzzle.py:999`、`quality.py:445`、`llm.py:5555` | 同上 | 消灭一整类经典形式 | **放宽** |
| 6 | 谜底 prompt 里的 "2~4 句" | `llm.py:2395` | 写作格式约束 | 压掉汤底"重新定性"的空间 | **删除**，只留字数上限 |

### 顺带发现的两个**纯 bug**（与风格无关，但确实存在）

* `_keywords_prompt()`（`llm.py:2183`）结尾写的是 **"直接给出谜面与谜底"**
  —— v3 时代的指令，与 v4 的"先交 core_truth"**矛盾**。上一轮接 Case-first
  时漏改。
* `PUZZLE_HARD_MAX_LEN = 220` / `ANSWER_HARD_MAX_LEN = 300` 在**前端代码里
  没有任何对应常量**（`web/app.js:545-580` 的 `layout()` 只做 58px→46px
  的逐级缩字号 + AutoScroller 兜底）。它们是**经验值**，不是画布硬合同 ——
  所以"220 是硬合同不能动"这个说法**在代码里不成立**，应该实测一次。

## 3. A / B / C 哪一臂更接近想要的红黑海龟汤？

**产品判断（样本 8/8/8，不构成统计结论）：**

### 汤面层：B ≈ C ≫ A

谜面长度就是最直接的信号：

| 臂 | 谜面字数（8 道） |
|---|---|
| A | 101 / 80 / 120 / 125 / 96 / 88 / 103 / 125 —— median **102** |
| B | 108 / 54 / 67 / 84 / 130 / 53 / 66 / 68 —— median **68** |
| C | 173 / 92 / 151 / 184 / 129 / 255 / 399 / 288 —— median **178** |

**B 的谜面明显更短、更"一个切片"。** 最好的几个例子：

> **B-6（black）**：寨里人说，看见水精灵的人会漂浮起来。今年，潭面真的浮起了一个人——可全村人的第一反应，是去翻他同事的抽屉。

53 字，**三个方向的提问欲**（精灵是什么 / 为什么浮起来 / 为什么翻抽屉），
而且"翻同事的抽屉"这个动作本身就是谜底（有人用传说封锁一条走私通道）
的**指向**而不泄露。这是 24 道里最接近任务书目标形态的一道。

> **B-8（black）**：科考站的气压计已经连续九天指向历史最低，老周却在这天早上拔掉了无线电的发射线，只留下接收。他对着话筒说了一句"我到了"，然后笑了。

68 字。谜底是他一直在跟**自己的回声**对话。揭晓后"我到了"这三个字
变了味 —— 这是"汤底让原场景变味"的教科书样本。

> **B-4（black）**：我推开门，丈夫坐在一地的照片中间。他抬起头，用很陌生的眼神看着我："你是谁？我为什么会有这么多……一个年轻女人的照片？"我愣在原地，因为照片上那个"年轻女人"，就是我。

**第一人称 + 对话体 + 没有问号** —— 三种当前 production 会**强行改掉**
的形式，全在这 84 个字里，而且它们正是让它好的原因。

### 汤底层：C ≫ B > A

C 的 Call 1 让"故事先完整存在"这件事**可验证**：24 道里只有 C 臂
产出了 `interesting_unknowns` 这种显式的"观众不知道什么"清单，
而 `askable_hidden_facts` 与 Call 1 的 unknowns 对得上 —— 说明
**"隐藏 ≠ 不公平"是可操作的**，不是口号。

C 的失败模式也很清楚：**它太能写了**。C7 的 Call 1 出了 1577 token 的
故事，Call 2 就截了个 399 字的汤面 —— **远超 220 的硬门**。所以 C 的
问题不是创意，是**没有长度的自我约束**。

### A 的问题不是"没有创意"，是"形状被压平"

A-3 和 A-6 证明 A 也能出好题。但 A 的 8 道里有 5 道的谜底是
"补一段之前没写的背景"（A-1 固件更新、A-2 睡眠障碍、A-4 路牌、
A-5 护士起外号、A-7 老师浇温水），而不是"重新定义谜面里已经写着的词"。

## 4. 两个关键词有帮助吗？

**有明显帮助（B/C 臂内部对照），但"不给"也完全可行。**

C1（有词，4 道）vs C2（无词，4 道）的差别**不在质量，在方向**：

| | C1 有词 | C2 无词 |
|---|---|---|
| 题材落点 | 被关键词锚死：邪术→阴司、冻死→极地、小学/苏联→哈尔滨 | 自己选：殡仪馆 ×2、磁带、掌心茧 |
| 创意密度 | 4 道里 2 道（CC1-1、CC1-4）非常好 | 4 道里 3 道（CC2-5、CC2-7、CC2-8）非常好 |
| 趋同风险 | 低（词逼它往外走） | **高** —— 4 道里 **3 道都落在殡仪馆/遗物** |

**结论：关键词的作用是"强制换题材"，不是"提高创意"。** 无词时模型
会往它自己的舒适区（殡葬/遗物/死亡）塌缩 —— C2 四道里三道都是这个。
所以两个关键词**值得保留**，但要认清它是**多样性工具**，不是质量工具。

⚠️ 附带发现：关键词在 Case-first 的四步里**没有任何落点**
（`_TOOL_KEYWORD_IDEA` 里没有 keywords 字段），system 里只有末尾一句
"自然融入即可"。它在 A 臂的实际效果就是"氛围提示"。

## 5. "完整故事 → 截取汤面" 比现在的 `core_truth → observed_clues → puzzle` 更自然吗？

**更自然，但有代价。证据：**

**支持（造 C 臂的直接观察）：**

1. **Call 1 里没有谜面** —— 模型是纯创作，不用同时想"怎么把它切成
   六格"。C 臂的 Call 1 普遍比 A 臂的 `core_truth` 长 3~5 倍且**没有
   一次出现 A-8 那种"先写一个解释再划掉"的自我怀疑**。
2. **`interesting_unknowns` 是自然产物**。C 臂能明确列出"观众不知道
   什么"，而 A 臂的 `observed_clues` 是"现场能看到什么" —— 这两件事
   不一样：前者是**问题清单**，后者是**证据清单**。任务书要的正是前者。
3. **`askable_hidden_facts` 让"公平"可验证**。C-2（冻死/极地）的
   `askable_hidden_facts` 有 5 条，全部能在 QA 里问出来，而汤面
   **一条都没写**。这是对 §1.6 那条 `fair_clue` 契约的**直接反例**：
   隐藏关键事实，题照样公平。

**代价：**

1. **长度失控**。C 的谜面 median 178 字，3 道超 220。Call 2 需要
   显式的长度约束。
2. **成本翻倍**。C 是 2 次调用，A/B 是 1 次。而且 Call 1 的输出
   会长（最高 1577 token），Token 成本更高。
3. **Call 1/2 之间会丢东西**。CC1-1 的 Call 1 里"林晚已死"是核心，
   Call 2 的汤面把它藏得很好 —— 但 C-4（小学/苏联）的 Call 2 汤面
   停在"我在等上课铃"，把 Call 1 里最强的"影子对上"那层丢了。
   **这是新的失败模式**：截取时选错了切片。

## 6. `static_gate` —— 好题出来之后会不会被当前框架卡住？

（确定性代码门，**0 LLM 调用**；Reviewer / truth audit 是 LLM，本轮没跑。
完整数据 `static_gate.json`。）

| 臂 | 谜面未以问号结尾 | 第一人称 | 谜面 > 220 **fail** | 汤底 > 300 **fail** | **完全干净** |
|---|---|---|---|---|---|
| A | 5/8 | 0/8 | 0/8 | 0/8 | **3/8** |
| B | 8/8 | 1/8（B-4） | 0/8 | 0/8 | **0/8** |
| C | 8/8 | 0/8 | 3/8 | 4/8 | **0/8** |

**这是本轮最重要的产物。**

* **B 臂 8/8 全部**因为"谜面结尾不是问句"被 `can_fix` ——
  而 `can_fix` 在这条上**实际是硬改**（`llm.py:5557` 把它放进
  `hard`，Reviewer 不改就 rewrite → 整稿丢弃）。
* **C 臂 8/8 同样**，另有 3 道超谜面长度、4 道超汤底长度（**直接 fail**）。
* A 臂自己也有 5/8 中招 —— **这条规则连当前生产自己的输出都在罚**。

也就是说：**"好题"和"能过当前代码门"在这批样本上几乎是两个不相交的集合。**
B-4、B-6、B-8、C-7 这些读起来最好的，全部会被卡。

这正好回答任务书 §十一 那个必须分开的问题：

> **不是生成 Prompt 出不来好题 —— 是 Prompt 一放宽，出来的好题就被
> 框架的形状门修坏或拒掉了。** 长度那两条（220/300）是真 fail，
> 需要实测前端；问号那条 24 道里 21 道中招，是最该先动的。

## 7. 最应该先放宽的 5 个 hard gate（按影响排序）

| # | 规则 | 为什么排这个位置 |
|---|---|---|
| **1** | **谜面结尾必须问号**（→ 改成"含可调查异常"） | 24 道里 **21 道**中招（A 5/8、B 8/8、C 8/8）。当前生产自己的输出都在被它罚。改它收益最大、风险最小 |
| **2** | **`fair_clues` 必须逐字预置 + 必须支持 required atom** | 闭环的**源头**。C 臂已给出反例：`askable_hidden_facts` 证明隐藏关键事实照样公平 |
| **3** | **"好不好玩"四项作为自由生成硬门**（降 soft） | 全灭单核经典汤。curated 侧已有完全相同的先例（`_CURATED_SIGNAL_FIELDS`），只差把同样推理用到自由生成 |
| **4** | **`discovery_beats` 强制 2~4**（改观察指标） | 结构上禁止单层翻转。B-6/B-8 这类单核题必然不合格 |
| **5** | **第一人称硬改第三人称** | B-4 是最好的一道之一，而它恰好是**第一人称 + 对话 + 无问号** |

（第 6 位是谜底 prompt 里的"2~4 句"写作格式 —— 它不改代码门，但压掉汤底
的重新定性空间。第 7 位是 Stage A 单调用承载创作+结构+文案。）

## 8. 如果下一轮接 production，最小改动方案（**只写建议，本轮不实施**）

按"改动小 / 收益大 / 风险低"排序：

**第一步（纯 bug，无产品决策）**

1. 修 `_keywords_prompt()` 结尾 —— "直接给出谜面与谜底" 与 v4 schema
   矛盾，改成与 Case-first 一致的口径。
2. 实测前端：在 46px 下量一次谜面/汤底的真实可显示字数，据此核实
   `220` / `300` 是否合理。**先量再改**。

**第二步（只放宽形状，不动质量政策）**

3. `has_closing_question` 从 `can_fix` 的**硬改**降为**不判**
   （或改成"含异常"的宽判据）。
4. `is_first_person` 从硬改降为 `warn`（只在指代歧义时 fix）。
5. 从谜底 prompt 里删掉"2~4 句"。

**第三步（动质量政策 —— 需要单独任务书）**

6. `_quality_check_contract()` 对自由生成链从 `[:9]` 收窄到正确性五项
   （`narrator_truthful` / `mechanism_consistent` / `core_answer_direct` /
   `completion_contract_minimal` / `livestream_safe`），其余降 soft。
   **这一步直接复用 curated 侧已验证的同一套推理**，不是新政策。
7. `discovery_beats` 从 `validate_spec` 的 fail 降为 metrics。
8. `fair_clues` 契约拆分 —— 这条最难，因为它连着 QA 的公平性保证，
   必须先设计"QA 可获得的证据"如何在运行时被验证。

**不建议这一轮做的**：把 B 或 C 的 prompt 直接搬进 production。
样本只有 8 道，而且 C 的长度失控需要先解决。应该先做 3/4/5（形状放宽），
再重跑一次 24 道，看**在放宽后的门下** B/C 能留下多少。
